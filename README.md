# Moss

A Typora-style Markdown editor built from scratch: you write in the text, and the page takes shape around it. No split preview, no side-by-side panes â€?the paragraph you are reading *is* the source.

![Moss](docs/screenshot.png)

## What it does

- **Live preview** â€?headings, bold, italic, inline code, strikethrough, links, quotes, lists, task lists and rules are styled in place. Put the caret inside an element and its raw syntax reappears, dimmed, so you can edit it directly.
- **Tables you can edit in place** â€?click any cell and type. `Tab` / `Shift+Tab` move between cells, `Enter` commits, `Esc` cancels. `Alt`+click drops the caret into the raw Markdown to add or remove rows.
- **Blocks** â€?fenced code with syntax highlighting for ~100 languages, GFM tables, horizontal rules.
- **Math** â€?inline `$...$` and display `$$...$$` through KaTeX.
- **Images** â€?`![alt](path)` renders inline; relative paths resolve against the opened folder.
- **Tabs, folder tree, outline** â€?open a folder, click through files, jump with the outline panel; the outline highlights the section you are reading as you scroll.
- **File watching** â€?an open file that changes on disk reloads itself (with your scroll position kept). If you have unsaved edits, Moss refuses to clobber them and says so instead.
- **Modes** â€?live / source, focus (dims everything but the caret's paragraph), typewriter (keeps the caret mid-screen).
- **Themes** â€?Paper, GitHub, Sepia, Night, Moss Dark.
- **Chinese UI** â€?the whole interface is localized (ä¸­æ–‡ / English, switchable in the â‹?menu and remembered). The welcome document has a Chinese edition too.
- **Export** â€?standalone HTML, or print to PDF through the browser.

## Run it

```bash
npm install
npm run dev            # http://127.0.0.1:5188
```

Production build:

```bash
npm run build
npm run preview        # serves dist/ on 5188
```

Desktop window without packaging:

```bash
npm run desktop        # runs dist/ in Electron; run `npm run build` first
MOSS_DEV=1 npm run desktop   # loads the dev server instead
```

> If your shell sets `ELECTRON_RUN_AS_NODE=1` (some agent harnesses do), Electron starts as plain Node and exits without showing a window. Clear the variable first: `Remove-Item Env:ELECTRON_RUN_AS_NODE`.

## Files

Browsers cannot write to disk directly, so Moss uses the **File System Access API** (Chrome / Edge, and Electron). `Open folder` asks for a directory handle, `Save` writes back through the same handle, and a 2.5-second poll compares the file's `lastModified` to detect outside edits. Firefox and Safari fall back to drag-and-drop plus downloads, with no watching.

## How it is built

```
src/
  editor/
    live-preview.ts   # the whole trick: a StateField that turns the syntax tree into decorations
    table.ts          # table model, cells with document offsets, in-place cell editor
    widgets.ts        # image, math, checkbox, bullet, rule widgets
    setup.ts          # CodeMirror 6 configuration
    format.ts         # bold/italic/link/heading commands
  ui/                 # tabs, tree, outline (with scroll-spy)
  io/files.ts         # File System Access wrappers, folder scan, mtime polling
  export/html.ts      # standalone HTML + print CSS
electron/main.cjs     # desktop shell (custom title bar, theme-aware window chrome)
electron/preload.cjs  # the one IPC bridge: the renderer tells the shell which colors to use
```

The editor is [CodeMirror 6](https://codemirror.net/). The live-preview layer walks the Lezer Markdown tree and, for every element that the selection is not touching, replaces the syntax marks with zero-width decorations and applies a CSS class instead.

Decorations live in a `StateField`, not a `ViewPlugin` â€?inside a plugin, decorations that replace a line break throw `RangeError`, which silently corrupts CodeMirror's height map and leaves the document full of phantom gaps.

Table cells carry their absolute document offsets as `data-from` / `data-to`. Clicking one opens a real `<input>` positioned over the cell; committing dispatches a change over exactly that range. Because positions are re-rendered after every edit, `Tab`-ing into the next cell always writes to the right place.

## Scope and honesty

This is an independent implementation written against public knowledge of how a live-preview Markdown editor behaves. It contains no code, styles, icons or theme files from Typora, and it is not a redistribution of Typora. Typora is a commercial product â€?if you need what it does, buy it.
